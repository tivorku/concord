# MDN: Market Decentralized Network

Децентрализованная сеть, направленная на координацию продавцов на платформе **«Маркет Т2»**.
---
## Суть проекта
Сейчас Маркет представляет из себя хаотичную платформу, где выигрывает не умный продавец, а удачливый. Маркет разделен на сегменты. Для участника каждого сегмента доступна возможность поднять шансы на покупку его лота покупателями, приобретя **поднятие на первое место среди других (aka "ракета")**. На данный момент продавцы соревновательно «сбивают» друг друга в борьбе за **первое** место в топе каждого сегмента рынка, тратя огромное количество ресурсов (**одна "ракета" обходится в 5 рублей**), при том, что эффективность такой стратегии **довольно низкая**. Я предлагаю решить проблему **трагедии общих ресурсов** внедрением **децентрализованной сети**, координирующей продавцов и упразняющей хаос. Работу сети проще описать сравнением:
*   Маркет без MDN: нерегулируемый перекрёсток с частыми ДТП и вечными пробками. Здесь каждый водитель в панике жмет на газ, пытаясь проскочить первым, в итоге все врезаются друг в друга, сжигая бензин и нервы, а прибыль получает только «владелец дороги» (Т2), собирающий плату за эвакуацию разбитых машин.
*   Маркет с MDN: регулируемый перекрёсток с эффективным **автономным диспетчером**. Все участники движения соединены в одну радиосеть: они точно знают свою очередь и проезжают на зеленый свет ровно тогда, когда это максимально выгодно системе. Нет ни паники, ни лишних трат, а «ДТП» случаются только если на перекресток влетает безумный одиночка, которого система тут же «вычисляет и изолирует».

# Архитектура
Архитектура разделена на два независимых компонента: **MDN Relay** и **MDN Client**.
## 🛰 MDN Relay
*Служебный узел инфраструктуры, обеспечивающий связность сети.*

*   **Внеполосная авторизация (HTTP Knock):** Реализация эндпоинта для регистрации PeerID. Автоматическое внесение IP-адреса клиента в Whitelist.
*   **Сетевой Оракул:** 
    *   **IP-шлюз:** Работа в режиме `Global DHT ModeServer` для обеспечения кворума Identify/AutoNAT клиентам за CGNAT.
    *   **Time Oracle:** Трансляция эталонного серверного времени для синхронизации эпох.
*   **MDN Routing:** Ведение локальной таблицы маршрутизации (`/mdenet`) для изоляции сети.

---

## 💻 MDN Client
*Автономный агент, выполняющий прикладную логику и участвующий в консенсусе.*

*   **Гибридное обнаружение (Discovery):** 
    *   **GossipSub:** Мгновенный поиск соседей через мета-топики (< 3 сек).
    *   **Local DHT:** Поиск прямых адресов для проксирования через локальный префикс (< 10 сек).
*   **Синхронизация и Время:**
    *   **Network Time Offset:** Калибровка времени относительно реле при старте.
    *   **Часы Лампорта:** Упорядочивание событий в распределенном реестре.
*   **Алгоритм консенсуса:** 
    *   **Fair Queuing:** Формула приоритета $P = S^2 / W$.
    *   **Sliding Window:** Принудительная дефляция Satiety ($S$) каждые 15 минут.
    *   **Uptime Penalty:** Заморозка Satiety при уходе в оффлайн (пропуск слайдинга).
*   **Вспомогательные технологии:**
    *   **Peer-as-Proxy:** L4-туннелирование прикладных запросов через соседей по Mesh-сети.
    *   **Fingerprinting:** Использование `uTLS` для эмуляции TLS-отпечатков мобильных устройств.
*   **Безопасность:**
    *   **State Reconciliation:** Автоматическое восстановление локального состояния при получении `SYNC` от сети.
